# Kouros — notes for Claude

Desktop app for runners (Windows): training, sleep, HRV, nutrition, supplements and a rule-based coach. UI language: Russian.

## Before any work
- This repository is **public**. The full project notes and the design document live in the private repository `Chartedkey/Kouros-private` (`CLAUDE.md`, `docs/KOUROS.md`). Attach it (add_repo) and read both before changing anything; keep them up to date there, never here.
- Never commit personal data to this repository: no names, body measurements, test results, health numbers, real exports or screenshots with data, keys or tokens.
- Never start building a new version until the owner explicitly confirms («давай», «начинай», «делай»).

## Stack (short)
- `src/` React 18 + TS + Vite; `src/lib/api.ts` wraps Tauri commands and has a browser demo backend.
- `src-tauri/` Tauri 2 + Rust; SQLCipher DB; migrations appended to `MIGRATIONS` in `db.rs` (never edit a shipped one). Readers use the TEMP VIEWs `hm` (health) and `va` (counted workouts).
- `src-tauri/src/engine/` std-only formulas; `*_svc.rs` services build the JSON for each screen.
- Catalog of supplements / medicine registry: `tools/catalog/build.py` via `.github/workflows/catalog.yml` → `src-tauri/resources/*.json.gz`.
- CI: `check.yml` on branch pushes (tsc, vite build, cargo check; Rust errors as annotations), `build.yml` on `main` builds the NSIS installer and publishes release `v<version>`. Bump the version in `package.json`, `src-tauri/tauri.conf.json`, `src-tauri/Cargo.toml` together and add a `## <version>` section to `CHANGELOG.md` (it becomes the release description).
- Demo data in `src/lib/api.ts` is fictional and must stay so.
- `src-tauri/src/food_dishes.rs` is generated by `tools/food/dishes.py` — edit recipes there.
- Releases are signed for the auto-updater: `build.yml` needs the repo secret `TAURI_SIGNING_PRIVATE_KEY`; the public key is in `tauri.conf.json`. Never commit the private key.
- Labs (0.20): `parse/pdf.rs` + `parse/labs.rs` read lab PDFs locally (std-only, testable with plain `rustc`); `labs_svc.rs` dictionary and notes. Never commit real lab reports or values from them — test with your own files outside the repo.
- Exercise library (0.22): `tools/exercises/build.py` (Free Exercise DB, public domain) + `tools/exercises/ru.tsv` → `src-tauri/resources/exercises.json.gz`, `public/ex/*.webp`; `exercise_svc.rs` (body-weight share, resistance bands in settings `bands`, effective load, muscle groups).
- Day choice and shoes (0.23): `plan_svc::check_choice` / `choose` / `confirm` (migration v19), `shoe_svc.rs` (pick a pair for today; characteristics in `shoes[].spec`, pasted review tables parsed in `components/Shoes.tsx` — never scrape review sites).
- Shoe mileage (0.23.1): only workouts the athlete assigned to a pair count (no automatic main pair); pick in the check-in, Обзор question or workout page; `shoe_runs` lists a pair's workouts; spec `membrane` used for wet/snow/heat.
- Navigation (1.0): `lib/nav.ts` `scrollToCard(aria-label)` + App `go({tab, sub, card})`; Coach `initialSub`; Today reminder links `SIGNAL_GO`; workouts opened from another tab go back there.
- Help (1.1): `src/help/content.ts` (chapters, sections, `cards` → «?» on matching cards via `lib/helptips.ts`), `pages/Help.tsx`, `components/HelpLayer.tsx`, `components/Tour.tsx`. Update the help text with every feature change. README screenshots in `.github/screens/` — demo data only.
- Muscle map (1.2): `tools/muscles/make.py` builds `public/muscles/*` (grey drawing, one mask per muscle group, label map); `components/MuscleMap.tsx` tints masks (green fresh, yellow tired, red overloaded).
- 1.3 Health Auto Export: `parse/hae.rs` (std-only streaming reader of HAE JSON v2 → Apple/freddy metric names), `hae.rs` (provider `HAE`, LAN receiver with key on port 8765, `Kouros\inbox`, folder scan, file import), `sources.rs` (HAE is Apple-like: no norm reset; pseudo-group `other`; `set_all`), UI `components/HealthAutoExport.tsx` + own QR encoder `lib/qr.ts`, help section `settings.hae`. Never commit real export files.
